## A1: canonical model — ✅ done (2026-09-09)

Boundary: add `project::CamJob` (schema 4) with operation enums, setup, tool model and
assignments, plus strict migration from legacy schema-3 jobs. Legacy algorithms unchanged.

Acceptance criteria (from plan section 18):

- [x] Old complete jobs round-trip through migration with all values and selection preserved.
      (`project_migration.rs`: schema-2 endmill-only `fixtures/m3/rectangle.json`, combined
      `fixtures/m4/contact-line.json`, and the real combined flower job
      `real_data/flower_box-svg.job-real.json` — value-level assertions per field plus a
      schema-4 JSON serialize/reload identity check.)
- [x] Old incomplete jobs round-trip with missing fields preserved as unset.
      (`incomplete_legacy_job_migrates_with_unset_values_preserved`: cleared planning block,
      stock thickness, depth and per-tool values stay `None`; endmill-only mode preserved.)
- [x] A Face operation can exist in a job with no SVG source.
      (`face_job_without_source_validates_and_round_trips`; incomplete face remains saveable.)
- [x] Duplicate operation/tool IDs are rejected. (`PROJECT_OPERATION_ID` / `PROJECT_TOOL_ID`.)
- [x] Unresolved tool/height references are rejected with located errors.
      (`PROJECT_TOOL_REFERENCE`, `PROJECT_HEIGHT_REFERENCE`, `HEIGHT_REFERENCE_FORWARD`,
      `HEIGHT_REFERENCE_INVALID`, `PROJECT_TOOL_KIND` — messages carry operation/tool IDs.)
- [x] Unknown job schemas are rejected. (`CAM_JOB_SCHEMA_VERSION` for versions 3/5;
      unknown operation kinds and unknown fields fail strict parsing as `PROJECT_JSON`.)
- [x] `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`,
      `cargo test --workspace --locked` pass (37 test targets ok, 0 failures, including the
      pre-existing suites).

Changed files: `crates/cam-core/src/project.rs` (new), `crates/cam-core/src/project/migrate.rs`
(new), `crates/cam-core/src/lib.rs` (module wiring), `crates/cam-core/tests/project_model.rs`
(new, 16 tests), `crates/cam-core/tests/project_migration.rs` (new, 7 tests). Additive-only
touches to legacy files for shared derives: `job.rs`, `model.rs`, `pocket/settings.rs`,
`vcarve/settings.rs` (`PartialEq` derives; no behavior change).

Behavior notes:

- `CamJob` schema 4 with `FlatVcarve | Face | Profile | DragKnife` settings, `SetupSettings`
  (stock thickness/XY, work zero incl. `StockAnchor` fractions 0/0.5/1, clearance, start),
  `JobTool` with pure geometry + one authoritative plunge capability in `ToolCapabilities`,
  `MillingAssignment`/`KnifeAssignment` with `spindle_direction` kept unset on migration.
- Migration maps legacy `endmill_planning.clearance_z_mm`/`start_xy_mm` to setup travel
  settings, rough budgets to the operation, `vbit_planning` presence to
  `Combined`/`EndmillOnly` mode, conflicting legacy plunge values rejected by the legacy
  validator before migration, machine profile preserved as `legacy_machine_profile`.
- Validation allows incomplete jobs to save (Options stay unset); structural errors
  (duplicate IDs, unknown references, forward height refs, misplaced `OperationTop`,
  mode/finish disagreement) are document errors even in disabled operations.

Remaining unsupported cases: CamJob is not yet consumed by planning, service DTOs, adapters
or UI (that is A2–A4); height references are validated structurally only (numeric
resolution arrives with B2); Face/Profile/DragKnife settings are document-contract fields
only — no planner exists yet; stock XY stays `None` for legacy jobs until supplied (B1).

## A2: sequence contract — ✅ done (2026-09-09)

Boundary: generic motions/stages/execution representation plus the Flat V-carve
compatibility adapter, planned against original stock-top geometry.

Acceptance criteria (from plan section 18):

- [x] Migrated flower and synthetic M4 jobs produce equivalent legacy motion
      geometry/order and completeness.
      (`sequence_plan.rs::migrated_m4_and_flower_plans_match_legacy_geometry_order_and_completeness`
      over `fixtures/m3/rectangle.json` (endmill-only), `fixtures/m4/contact-line.json`
      (combined with an empty rough stage) and the real combined flower job:
      per-motion start/end/layer/feed equality in order, interpolation/effect equal to
      the old writer's actual G0/G1 and cutting semantics, stage ranges exact,
      execution items `ToolChange → SetProcessIntent → RunStage` in order.
      `adapter_reconstructs_the_migrated_legacy_job` proves the adapted legacy job is
      value-identical to the migrated source, modulo the redundant endmill slot
      plunge spelling.)
- [x] Two independent operations have distinct identities.
      (`two_independent_operations_keep_distinct_identities`: unique stage IDs
      namespaced by operation, dense global motion IDs with one contiguous range per
      operation, recurring tools re-selected in execution order without regrouping
      motions by tool, input/execution fingerprints differ from the single-op plan.)
- [x] Extra contract behaviors: missing machining fields yield an `incomplete`
      operation result with located diagnostics (never a silent skip); unsupported
      enabled operations fail with `OPERATION_PLANNER_UNAVAILABLE`; budget-exhausted
      fixtures report `inconclusive`, not success; every linear-feed motion carries a
      feed; V-bit pass IDs derive from recorded legacy executions; unresolved spindle
      direction is recorded as an export `preparation_requirement`, not executable
      state. (`sequence_plan.rs`, 7 tests.)

Changed files: `crates/cam-core/src/toolpath.rs` (new), `crates/cam-core/src/sequence.rs`
(new), `crates/cam-core/src/operations/mod.rs` (new), `crates/cam-core/src/operations/flat_vcarve.rs`
(new), `crates/cam-core/src/lib.rs` (module wiring), `crates/cam-core/tests/sequence_plan.rs`
(new, 7 tests).

Test evidence: `cargo test -p cam-core --locked --test sequence_plan` → 7 passed;
`cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`,
`cargo test --workspace --locked` all pass (0 failures).

Remaining unsupported cases: plans use original stock-top geometry (prefix stock
history arrives in B2); `OperationPlan` is produced in cam-core only — it is not yet
served through cam-service DTOs, native/WASM adapters or the web UI (A4), cannot be
exported (A3 writer/reader), and Face/Profile/DragKnife operations are rejected rather
than planned (C/D/F). Empty legacy rough stages are skipped rather than emitted as
empty stages.

## A3: core checks/post split — ✅ done (2026-09-09)

Boundary: automatic basic checks separated from M5 detailed quality; generic ordered
LinuxCNC writer/reader for sequence plans; schema-1 profile application; trusted
retained-plan handling for imported plans.

Acceptance criteria (from plan section 18):

- [x] New sequence export works without running detailed quality.
      (`sequence_export.rs::sequence_export_works_without_running_detailed_quality` and
      `combined_fixture_exports_through_the_sequence_pipeline`: `check_plan` →
      `PreparedExecution::prepare` → emit → independent readback; M5/`verify_motions` is
      never invoked on this path. `legacy_quality_analysis_remains_callable_alongside_sequence_export`
      proves the legacy planner/analysis still run.)
- [x] Altered motion order/process state are rejected.
      (`altered_motion_order_or_coordinates_are_rejected_by_readback`: swapped motion
      blocks, edited coordinates, changed tool numbers and removed spindle starts are
      rejected with `POST_SEQUENCE_MISMATCH` / `PROCESS_SPINDLE_STATE` by a reader that
      trusts only the numeric bytes.)
- [x] Forged imported receipts are rejected.
      (`forged_imported_plans_and_receipts_are_rejected`: `TrustedPlan::import` replans
      the embedded job and compares motions/stages/execution/fingerprints — edited
      motions, recomputed-looking fingerprints, dropped motions and foreign engine
      versions are all rejected; only regeneration can establish trust.)
- [x] Behavior details: basic checks (`checks.rs`) cover generation completeness, dense
      motion IDs, stage ownership/order/coverage, finite coordinates, positive feeds on
      linear feeds, no feeds on rapids, effect/role agreement and full execution
      accounting (tool change → intent → run per stage, nothing extra). Unresolved
      spindle direction blocks process preparation (`PROCESS_SPINDLE_STATE`) but not
      generation, and is recorded as a preparation requirement. Schema-2 sequence
      profiles map any number of job tools exactly once, carry no `z_datum` and no
      per-tool spindle direction (strict parsing rejects both). Applying the real
      schema-1 profile moves its Z datum into `setup.work_zero.z` and its per-tool
      directions into matching assignments as one application. Stock-bottom Z-datum
      export shifts Z by stock thickness (machine Z13.000 for clearance 5 over 8 mm);
      XY work-zero transforms are explicitly rejected until B1. 13 tests in
      `tests/sequence_export.rs`.

Changed files: `crates/cam-core/src/checks.rs` (new), `crates/cam-core/src/post/sequence.rs`
(new), `crates/cam-core/src/post/mod.rs` (module wiring), `crates/cam-core/src/sequence.rs`
(`TrustedPlan`), `crates/cam-core/src/lib.rs` (module wiring), additive `PartialEq` derives
in `post/profile.rs` (`M6Contract`, `M6Return`), `crates/cam-core/tests/sequence_export.rs`
(new, 13 tests).

Test evidence: `cargo test -p cam-core --locked --test sequence_export` → 13 passed;
`cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets --locked -- -D
warnings` pass; `cargo test --workspace --locked` passed three consecutive times. One
pre-existing flake was observed once in `cam-server` `library_routes_enforce_session_identity_strict_fields_and_metadata_limit`
(it also failed on a clean stashed tree with none of these changes, and passes in every
other run, in isolation and under repetition — unrelated to this work, recorded for
honesty).

Remaining unsupported cases: one ordered program only (sequential split files from
section 14.5 are not implemented); the legacy `post::process()` M5-gated path remains for
the legacy UI and is retired when A4 migrates the adapters; XY work-zero output
transforms and physical stock rectangles arrive in B1 (explicit rejection until then);
`analyze_quality` for sequence plans is not yet wired (legacy V-carve M5 remains the
callable detailed analysis); prefix-scope planning (`through_operation`) is not exposed.
